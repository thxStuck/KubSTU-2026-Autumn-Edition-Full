# Mobile Waf 2

> **Категория:** Beginner / PPC · **Событие:** KubSTU CTF 2026 Autumn
> Команда-автор: mpei_larpers · Источник: https://ctftime.org/writeup/41135 (CTFtime, сообщественный райтап)

## 📌 Задание

Сервис на 193.168.46.146:31832 — «WAF Gauntlet». Играет 100 раундов: присылает JSON с описанием запроса (метод, путь, query, заголовки, тело) и ждёт в ответ одну строку — `allow` или `block`. Блокировать надо только запросы с реальной исполняемой атакой (XSS, SQLi, SSTI, SSRF, инъекции команд, XXE/NoSQL/десериализация, HTTP-злоупотребления, LFI/path traversal), а всё остальное, включая хитрые безобидные двойники, пропускать. Ошибся — игра кончилась. По 3 секунды на раунд и 150 на соединение.

## 🏁 Решение

Главная слабость сервиса — он сам объясняет ошибки. На неверный ответ прилетает `# wrong at round N: expected block (xss)` и соединение закрывается, то есть класс атаки раунда утекает прямо в тексте ошибки. Отсюда сбор датасета: стратегия «всё allow» падает на первом же раунде с атакой (и сервис сам говорит, на какой), стратегия «всё block» — на первом безобидном. Раунд считается подтверждённым, только когда пришёл следующий, так что метки не угаданные, а точные.

Так набирается корпус: 325 подтверждённых сэмплов и ещё около 500 раундов с проставленным типом атаки. Никакой бинарь реверсить не надо — вся задача превращается в классификацию.

Дальше классификатор на правилах (waf_filter.py). Каждое поле разворачивается в несколько представлений — сырое, url-decode до трёх раз, со срезанными SQL-комментариями, %uXXXX, HTML-энтити, base64-блобы — и прогоняется по наборам правил на класс. Из интересного в правилах: JWT с `alg:none`, Shellshock, tar с `--checkpoint-action=exec`, `powershell -enc`, ImageMagick с `-write`, Log4Shell, блобы .NET BinaryFormatter и Ruby Marshal, base64-обёрнутые SSRF-цели, CRLF, request smuggling, X-Forwarded-Host, HTTP parameter pollution, path confusion. Не менее важно не тормозить безобидные двойники: экранированную разметку в тексте, шаблонные переменные вида `{{customer_name}}`, SQL-слова внутри обычной речи, `file://` в прозе, чувствительно выглядящие имена в нормальных URL.

Оффлайн-валидация: 0 расхождений на 497 типизированных сэмплах и 0 на 325 подтверждённых. Живой прогон: `python3 solve.py` прошёл 100/100 с первой попытки, сервис прислал `# cleared 100/100` и флаг в JSON:

```
{"flag": "kubstu{w4f_g4untl3t_100_r0unds_e7075354d674}"}
```
