# Last chance

> **Категория:** Forensics · **Событие:** KubSTU CTF 2026 Autumn

## 📌 Задание

Дан подозрительный PDF-файл. Нужно проанализировать его и восстановить спрятанный флаг.

**Файлы:** [solve.py](../../../assets/Forensics/Last%20chance/solve.py)

## 🏁 Решение

Первым делом при анализе подозрительного PDF стоит проверить его свойства и метаданные. Это можно сделать с помощью `exiftool`, `pdfid` или просто открыв файл в текстовом редакторе и поискав словарные объекты.

### Шаг 1: Анализ метаданных
В полях метаданных **Author** (Автор) и **Subject** (Тема) обнаруживаются странные строки в формате Base64:
- **Author**: `QR_PART1:<base64_данные>`
- **Subject**: `QR_PART2:<base64_данные>`

### Шаг 2: Восстановление QR-кода
Извлекаем обе строки, декодируем их из Base64 в формат PNG. Получаем две половины изображения. Склеив их вертикально (верхнюю над нижней), мы получаем полноценный QR-код.

При сканировании QR-кода получаем значение соли для AES:
```text
salt=7f3c92a1b4e5
```

### Шаг 3: Поиск скрытых объектов в структуре PDF
PDF-файлы позволяют хранить объекты, которые не отображаются визуально. Используем `pdf-parser` или поиск по строке `obj`. Мы находим три подозрительных объекта, добавленных в конец файла:

1.  **Объект 100 (`/JBIG2Decode`)**: Внутри потока данных (stream) спрятан вектор инициализации (**IV**). Данные представлены в виде hex-строки.
    *   **IV**: `a1b2c3d4e5f67890` (извлекается по смещению 11 в байтовом представлении).

2.  **Объект 101 (`/Sig`)**: Объект цифровой подписи, содержащий ASN.1 DER структуру в поле `/Contents`. Внутри структуры под нестандартным тегом `0x80` спрятана первая часть флага.
    *   **Part 1**: `part1_f4k3_s1g`

3.  **Объект 102 (`/Crypt`)**: Содержит зашифрованный поток данных в hex-формате — наш финальный флаг.

### Шаг 4: Дешифровка флага
Теперь у нас есть все компоненты:
- **Соль (из QR)**: `7f3c92a1b4e5`
- **IV (из объекта 100)**: `a1b2c3d4e5f67890`
- **Шифротекст**: из объекта 102
- **Первая часть флага (из объекта 101)**: `part1_f4k3_s1g`

Ключ для AES-256 вычисляется как SHA-256 хеш от конкатенации соли и IV:
$$\text{Key} = \text{SHA256}(\text{Salt} + \text{IV})[:32]$$

Используя алгоритм AES-256-CBC с полученным ключом и IV, расшифровываем данные из объекта 102.
