# bank3

> **Категория:** Crypto · **Событие:** KubSTU CTF 2026 Autumn

## 📌 Задание

Телеграм-бот «банк». Он умеет:

- `/register <имя>` — открыть счёт, получить «сертификат» (`.cert`);
- кнопка **«Сертификаты»** — выпустить сколько угодно сертификатов, в т.ч. **много на один счёт** (встроенный намёк: «нужно много подписей» ⇒ крипто, а не веб);
- `/login` — прислать `.cert`; вход под счётом **`admin` = флаг**;
- зарегистрировать `admin` напрямую **нельзя**.

Формат сертификата:

```
-----BEGIN KUBSTU BANK CERTIFICATE-----
account:   KB-319D02F03C
issued:    1791579938
signature: base64( r || s )     # по 32 байта
-----END KUBSTU BANK CERTIFICATE-----
```

`signature` — **ECDSA-подпись (secp256k1)** над именем счёта (`e = sha256(name) mod n`), `account_id = base64(r‖s)`.

Победа: предъявить валидную подпись для `admin` (зарегистрировать его нельзя) ⇒ нужно **восстановить приватный ключ сервера** и подписать `admin` самому.

**Файлы:** [solve_blackbox.py](../../../assets/Crypto/bank3/solve_blackbox.py)

## 🏁 Решение

### Уязвимость
Ключ сервера `d` постоянный. Слабость — в **nonce**: он не полностью случаен, а собран из трёх частей:

```
k = prefix·2^253  +  core·2^3  +  postfix
     └ 3 бита ┘       └ 250 бит ┘   └ 3 бита ┘
```

- `prefix` (старшие 3 бита) и `postfix` (младшие 3 бита) детерминированы по имени счёта (`sha256("prefix:"+name)%8`, `sha256("postfix:"+name)%8`);
- случайны только средние **250 бит** (`core`, свежий CSPRNG на каждую подпись).

Итого **6 структурированных (не случайных) бит в nonce** ⇒ классическая **Hidden Number Problem (HNP)** на смещённом nonce ECDSA. 250 случайных бит не перебрать, но 6 «утечки» достаточно, чтобы решёткой восстановить `d`.

Для **всех** подписей одного счёта `prefix` и `postfix` **одинаковы** (имя одно) — поэтому атаку можно провести, собрав подписи **с одного аккаунта** (что бот и позволяет).

### Сведение к HNP
Для подписи: `s·k = e + r·d (mod n)`. Подставляя `k = prefix·2^253 + core·8 + postfix` и обозначив известную часть `Aabs = prefix·2^253 + postfix`:

```
core = (s^-1·e − Aabs)·8^-1  +  (s^-1·r·8^-1)·d      (mod n),   0 ≤ core < 2^250
     =          B_i          +         A_i · d
```

Это HNP: ищем `d`, при котором все `core_i = A_i·d + B_i (mod n)` малы (`< 2^250`). Строим решётку Боне–Венкатесана, редуцируем, читаем `d` из короткого вектора.

**Custom-твист (анти-слоп):** известны и старшие, и младшие биты, неизвестна середина — из-за младших появляется множитель `8^-1` в `A_i, B_i`. Типовой MSB-only HNP-солвер из интернета ставит решётку неверно; линеаризацию надо вывести самому. Паблик-ключ **не нужен** — `d` проверяется структурно (все `core_i < 2^250`).

### Путь игрока (без исходника, чёрный ящик)
Исходника нет, `prefix/postfix` неизвестны, сам nonce не виден. Но:

1. Опознать `signature` = `r‖s` ⇒ ECDSA/secp256k1, подписывается имя (`e = sha256(name)`).
2. Собрать **много подписей с одного счёта** (≥ ~70, с запасом 120+).
3. Проверить повтор `r` — его нет ⇒ не nonce-reuse, а **смещённый nonce**.
4. Ключевой инсайт: у nonce есть **фиксированная, но неизвестная** часть в старших/младших битах, одинаковая на всём наборе (один счёт). Таких бит мало ⇒ их можно **перебрать**, а гипотезу проверять **структурно** (все `core_i` должны выйти `< 2^250`) — даже не обращаясь к боту.
5. Свип по небольшим `(a, c)` (сколько фикс. старших/младших бит) и по всем `2^(a+c)` значениям смещения `Aabs`; на верной гипотезе решётка выдаёт `d`.
6. Подписать `admin` ключом `d`, собрать `.cert`, отправить `/login` → флаг.

### Эталон и числа (проверено)
**Если структура известна** (внутренняя проверка, `admin/solve.py`): сбалансированный/рецентрированный базис, **plain LLL достаточно** (BKZ не обязателен, только фолбэк):
- порог: ~70 подписей чистым LLL (8/8 в тестах), ~50 с BKZ-фолбэком;
- время: **~2.5 c** на 120 подписях; восстановление `d` → форж `admin`.

**Чёрный ящик** (как у игрока): перебор `2^(3+3)=64` смещений внутри решётки, приём по структурному bound на `core`:
- время: **~60 c**, восстанавливает тот же `d`.

**Проверено на живом ТГ-боте:** 151 сертификат с одного счёта (`KB-319D02F03C`) → ключ восстановлен (чёрным ящиком) → сфоржённый `admin.cert` принят ботом → флаг. То есть таск решаем именно в том виде, в каком его получают игроки.

```python
# ядро решётки (сбалансированный базис; plain LLL)
M = IntegerMatrix(m+2, m+2); F = 1<<7; Kh = (1<<250)>>1
for i in range(m): M[i,i] = N*F
for j in range(m):
    M[m,j]   = A[j]*F
    M[m+1,j] = ((B[j]-Kh) % N)*F
M[m,m] = 1; M[m+1,m+1] = Kh*F
LLL.reduction(M)                      # BKZ только если LLL не дал d
# d читается из строки с |last| == Kh*F; валидация: все (A_i d + B_i) % N < 2^250
```
