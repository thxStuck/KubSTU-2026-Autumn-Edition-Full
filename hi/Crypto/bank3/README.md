एक Telegram «बैंक» बॉट। यह कर सकता है:

- **«Certificates»** बटन — जितने चाहें उतने सर्टिफ़िकेट जारी करें, जिसमें **एक ही खाते के लिए कई** भी (एक अंतर्निहित संकेत: «कई हस्ताक्षर चाहिए» ⇒ क्रिप्टो, वेब नहीं);
- `/login` — एक `.cert` भेजें; **`admin`** खाते से लॉगिन **= फ़्लैग**;
- `admin` को सीधे पंजीकृत करना **संभव नहीं**।

सर्टिफ़िकेट प्रारूप:

```
-----BEGIN KUBSTU BANK CERTIFICATE-----
account:   KB-319D02F03C
issued:    1791579938
signature: base64( r || s )     # по 32 байта
-----END KUBSTU BANK CERTIFICATE-----
```

`signature` खाते के नाम पर एक **ECDSA हस्ताक्षर (secp256k1)** है (`e = sha256(name) mod n`), `account_id = base64(r‖s)`।

जीत: `admin` के लिए एक वैध हस्ताक्षर प्रस्तुत करना (जिसे पंजीकृत नहीं किया जा सकता) ⇒ आपको **सर्वर की निजी कुंजी पुनः प्राप्त** करनी होगी और `admin` को स्वयं साइन करना होगा।

## 🏁 समाधान

### भेद्यता
सर्वर की कुंजी `d` स्थिर है। कमज़ोरी **nonce** में है: यह पूरी तरह यादृच्छिक नहीं, बल्कि तीन भागों से बना है:

```
k = prefix·2^253  +  core·2^3  +  postfix
     └ 3 бита ┘       └ 250 бит ┘   └ 3 бита ┘
```

- `prefix` (ऊपरी 3 बिट) और `postfix` (निचले 3 बिट) खाते के नाम से नियतात्मक हैं (`sha256("prefix:"+name)%8`, `sha256("postfix:"+name)%8`);
- केवल बीच के **250 बिट** यादृच्छिक हैं (`core`, हर हस्ताक्षर के लिए ताज़ा CSPRNG)।

कुल मिलाकर nonce में **6 संरचित (गैर-यादृच्छिक) बिट** ⇒ पक्षपाती ECDSA nonce पर एक क्लासिक **Hidden Number Problem (HNP)**। 250 यादृच्छिक बिट को ब्रूट-फोर्स नहीं किया जा सकता, पर 6 «लीक» बिट `d` को जाली से पुनः प्राप्त करने के लिए पर्याप्त हैं।

एक ही खाते के **सभी** हस्ताक्षरों के लिए `prefix` और `postfix` **समान** होते हैं (नाम एक ही है) — इसलिए हमला **एक ही अकाउंट से** हस्ताक्षर इकट्ठा करके किया जा सकता है (जिसकी बॉट अनुमति देता है)।

### HNP में रूपांतरण
हस्ताक्षर के लिए: `s·k = e + r·d (mod n)`. `k = prefix·2^253 + core·8 + postfix` प्रतिस्थापित करके और ज्ञात भाग को `Aabs = prefix·2^253 + postfix` से निरूपित करके:

```
core = (s^-1·e − Aabs)·8^-1  +  (s^-1·r·8^-1)·d      (mod n),   0 ≤ core < 2^250
     =          B_i          +         A_i · d
```

यह HNP है: हम ऐसा `d` खोजते हैं जिसके लिए सभी `core_i = A_i·d + B_i (mod n)` छोटे हों (`< 2^250`)। हम एक Boneh–Venkatesan जाली बनाते हैं, उसे रिड्यूस करते हैं, और एक छोटे वेक्टर से `d` पढ़ते हैं।

**कस्टम ट्विस्ट (एंटी-स्लॉप):** ऊपरी और निचले दोनों बिट ज्ञात हैं, पर बीच अज्ञात है — निचले बिट के कारण `A_i, B_i` में एक `8^-1` गुणक प्रकट होता है। इंटरनेट से मिला सामान्य MSB-only HNP सॉल्वर जाली को ग़लत तरीक़े से सेट करता है; रैखिककरण स्वयं निकालना पड़ता है। सार्वजनिक कुंजी **आवश्यक नहीं** — `d` को संरचनात्मक रूप से सत्यापित किया जाता है (सभी `core_i < 2^250`)।

### खिलाड़ी का रास्ता (बिना सोर्स, चॉक-बॉक्स)
सोर्स नहीं है, `prefix/postfix` अज्ञात हैं, nonce स्वयं दिखता नहीं। परंतु:

1. `signature` = `r‖s` पहचानें ⇒ ECDSA/secp256k1, नाम पर हस्ताक्षर होता है (`e = sha256(name)`)।
2. **एक ही खाते से कई हस्ताक्षर** इकट्ठा करें (≥ ~70, गुंजाइश के साथ 120+)।
3. `r` की पुनरावृत्ति जाँचें — कोई नहीं ⇒ nonce-reuse नहीं, बल्कि **पक्षपाती nonce**।
4. मुख्य अंतर्दृष्टि: nonce के ऊपरी/निचले बिट में एक **निश्चित, पर अज्ञात** भाग है, जो पूरे सेट में समान है (एक खाता)। ऐसे बिट कम हैं ⇒ उन्हें **ब्रूट-फोर्स** किया जा सकता है, और परिकल्पना को **संरचनात्मक रूप से** जाँचा जा सकता है (सभी `core_i` को `< 2^250` निकलना चाहिए) — बॉट से संपर्क किए बिना भी।
5. छोटे `(a, c)` (कितने निश्चित ऊपरी/निचले बिट) पर और ऑफ़सेट `Aabs` के सभी `2^(a+c)` मानों पर स्वीप करें; सही परिकल्पना पर जाली `d` दे देती है।
6. `admin` को कुंजी `d` से साइन करें, `.cert` बनाएँ, `/login` भेजें → फ़्लैग।

### संदर्भ और संख्याएँ (सत्यापित)
**यदि संरचना ज्ञात है** (आंतरिक जाँच, `admin/solve.py`): संतुलित/पुनर्केंद्रित आधार, **सादा LLL पर्याप्त है** (BKZ आवश्यक नहीं, केवल फ़ॉलबैक):
- सीमा: शुद्ध LLL से ~70 हस्ताक्षर (परीक्षणों में 8/8), BKZ-फ़ॉलबैक के साथ ~50;
- समय: 120 हस्ताक्षरों पर **~2.5 से**; `d` की पुनर्प्राप्ति → `admin` का फ़ोर्ज।

**चॉक-बॉक्स** (जैसा खिलाड़ी के पास): जाली के भीतर `2^(3+3)=64` ऑफ़सेट का ब्रूट-फोर्स, `core` पर संरचनात्मक bound द्वारा स्वीकृति:
- समय: **~60 से**, वही `d` पुनः प्राप्त करता है।

**लाइव TG बॉट पर सत्यापित:** एक ही खाते (`KB-319D02F03C`) से 151 सर्टिफ़िकेट → कुंजी पुनः प्राप्त (चॉक-बॉक्स से) → फ़ोर्ज किया गया `admin.cert` बॉट द्वारा स्वीकृत → फ़्लैग। अर्थात् टास्क ठीक उसी रूप में हल होने योग्य है जिस रूप में खिलाड़ी उसे पाते हैं।

```python
# ядро решётки (сбалансированный базис; plain LLL)
M = IntegerMatrix(m+2, m+2); F = 1<<7; Kh = (1<<250)>>1
for i in range(m): M[i,i] = N*F
for j in range(m):
    M[m,j]   = A[j]*F
    M[m+1,j] = ((B[j]-Kh) % N)*F
M[m,m] = 1; M[m+1,m+1] = Kh*F
LLL.reduction(M)                      # BKZ только если LLL не дал d
# d читается из строки с |last| == Kh*F; валидация: все (A_i d + B_i) % N < 2^250
```
