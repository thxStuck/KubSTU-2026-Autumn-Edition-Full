## 🏁 समाधान

### सार
`capy256k1.py` की घरेलू अंकगणित **कहीं भी यह जाँच नहीं करती कि बिंदु कर्व पर है**। यह एक क्लासिक **invalid curve attack** है।

लैब ने मानक secp256k1 नहीं, बल्कि अपनी 256-बिट कर्व भेजी (`a = 0`, विशेष रूप `2²⁵⁵ + c` का अपना प्राइम `p`)। मुख्य अंतर: **प्राइम twist-secure नहीं चुना गया है**। j-इनवेरिएंट 0 वाली कर्व पर सेक्स्टिक ट्विस्ट `y² = x³ + b` के छह में से एक क्रम होते हैं, जो CM निरूपण `4p = L² + 27M²` द्वारा निर्धारित होते हैं। इस `p` के लिए कई ट्विस्ट **2³⁴…2³⁹ परास में अभाज्य क्रम `q`** का उपसमूह रखते हैं।

`output.json` में कई डायग्नॉस्टिक बिंदु हैं, हर एक के लिए परिणामी बिंदु `R = secret · point`। बिंदु आधार कर्व पर नहीं, बल्कि इन कमज़ोर ट्विस्ट पर स्थित हैं।

यहाँ उपसमूहों को जान-बूझकर 2³⁴…2³⁹ परास में उठाया गया है। रैखिक स्वीप (`q` ऑपरेशन) का अर्थ है अरबों बिंदु-जोड़, जो शुद्ध Python में घंटों-दिनों लेता है — यानी **ब्रूट-फोर्स से नहीं निकलता**। एक असली टूलचेन चाहिए:

1. **invalid curve पहचानें** — कोई on-curve जाँच नहीं है।
2. हर बिंदु के लिए **`b = y² − x³ (mod p)` पढ़ें** (`a = 0`)।
3. **Sage के बिना ट्विस्ट का क्रम गणना करें** — CM-विधि `4p = L² + 27M²` (cornacchia `(L, M)` देता है, जिससे छह उम्मीदवार-क्रम); वह चुनें जो बिंदु को एनिहिलेट करे।
4. **`q` निकालें** — क्रम का गुणनखंड करें (trial division + Pollard rho / ECM), वह अभाज्य गुणनखंड खोजें जिसके लिए `q·point = O`।
5. **उपसमूह ⟨point⟩ में ECDLP** — baby-step/giant-step (या Pollard rho / kangaroo), `O(√q) ≈ 2¹⁷…2²⁰`, `R = secret·point` से `secret mod q` प्राप्त करें।
6. चार अवशेषों पर **CRT**।

सीक्रेट 128-बिट है; चार `q` का गुणनफल एक **142-बिट** CRT मॉड्यूलस `> 2¹²⁸` देता है, अतः मान अद्वितीय है। इसके बाद `decrypt_flag(secret, ciphertext)`।

Sage चरण 3–5 को तेज़ करता है, पर **अनिवार्य नहीं**: पूरा रास्ता शुद्ध Python में तय किया जा सकता है (cornacchia + rho + BSGS + CRT)।
