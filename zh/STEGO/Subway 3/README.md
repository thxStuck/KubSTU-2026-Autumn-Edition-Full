## 🏁 解答

> **状态：** 解题方法 ✅

### 描述

给出了一个包含 Subway Surfers 跑酷录像的压缩包（与题目 [Subway 2](../Subway%202/) 一样）。没有明显的文字——信息是通过屏幕上发生的事情来编码的。

### 思路

在每个视频里，你需要**数一数角色驶过 / 驶上的车厢（火车）数量**。得到的数字就是 flag 中一个字符的**十进制 ASCII 码**。

把各视频的字符**按顺序**拼接起来，就得到 flag。

```
видео_1 -> N1 вагонов -> chr(N1)
видео_2 -> N2 вагонов -> chr(N2)
...
флаг = chr(N1) + chr(N2) + ... 
```

### 分步解法

1. 解压压缩包，按文件名对视频排序（顺序很重要——它决定了字符的顺序）。
2. 对每个视频，数出一局跑酷中的车厢数量。将视频切分成帧、手动或半自动计数很方便：
   ```bash
   # по одному видео: нарезать кадры (например, 5 кадров в секунду) для удобного подсчёта
   ffmpeg -i "video_01.mp4" -vf fps=5 frames_01/%04d.png
   ```
3. 按 ASCII 表把每个数字转换成一个字符，拼接成字符串。

### 解码脚本

一旦得到各视频的车厢数量（按文件顺序），flag 就按如下方式拼接：

```python
# counts — список: количество вагонов в каждом видео, по порядку
counts = [
    # 75, 85, 66, 83, 84, 85, 123, ...   # пример: K U B S T U {
]

flag = "".join(chr(n) for n in counts)
print(flag)
```

正确性很容易从开头检验：前几个数字应当得到 `KubSTU{`——也就是 `75 85 66 83 84 85 123`。如果开头对不上，说明某处计数或文件顺序出错了。

### Flag

```
KubSTU{...}
```
> 确切的值取决于压缩包里的视频（我们目前手头没有这些视频）。
> 一旦填入 `counts`，上面的脚本就会自动拼出它。

### 注意事项

- 这与 Subway 2 的机制相同（那里数的是金币），但这里数的是**车厢**。
- 错误的主要来源是文件顺序被打乱以及漏数 / 重复计数车厢；请对照 `KubSTU{` 前缀检查。
